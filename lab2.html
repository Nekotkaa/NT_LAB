1. Theoretical part

1.1. Transport Layer Concepts (TCP, UDP, and Ports)

TCP Protocol (Transmission Control Protocol)

  • TCP operates as a stateful, connection-oriented protocol at the transport layer.
  • It ensures that transmitted data reaches the destination intact, in sequential order, and free of duplicates.
  • Reliability is achieved via sequence numbering, acknowledgments (ACKs), retransmission of missing segments, sliding-window flow control, and congestion control mechanisms.
  • It is chosen for applications prioritizing data integrity over minimal delay, such as HTTP/HTTPS, SSH, FTP, and SMTP.

UDP Protocol (User Datagram Protocol)

  • UDP is a stateless, connectionless, best-effort transport-layer protocol.
  • It transmits standalone messages called datagrams without prior connection setup or guarantees regarding delivery, ordering, or duplicate removal.
  • By avoiding handshakes, retransmission logic, and heavy session state, UDP keeps latency low and header overhead minimal.
  • It is widely used for time-sensitive or request-response traffic, including DNS, VoIP, multiplayer games, and live streaming.

TCP Protocol Parameters (Header Fields)

A standard TCP segment header (typically 20 bytes without options) contains the following fields:

  • Source Port & Destination Port (16 bits each): Identify the origin and target application processes on each host.
  • Sequence Number (32 bits): Marks the byte-stream offset of the first payload byte in the segment (or the initial sequence number when SYN is set).
  • Acknowledgment Number (32 bits): When the ACK flag is active, indicates the next sequence number expected by the sender.
  • Data Offset / Header Length (4 bits): Specifies the header length in 32-bit words, showing where user payload data starts.
  • Control Flags (e.g., SYN, ACK, FIN, RST, PSH, URG): Manage connection establishment, keepalive/maintenance, data flushing, resets, and termination.
  • Window Size (16 bits): Announces how many bytes the receiver can currently buffer (flow control).
  • Checksum (16 bits): Provides error checking over the TCP header, payload, and IP pseudo-header.
  • Urgent Pointer (16 bits): Points to priority/urgent bytes when the URG flag is enabled.

UDP Protocol Parameters (Header Fields)

A UDP header has a fixed size of 8 bytes and consists of four fields:

  • Source Port (16 bits): Identifies the sender's port (optional; may be set to 0 when unused or not required for replies).
  • Destination Port (16 bits): Identifies the target port on the destination host.
  • Length (16 bits): Defines the combined byte length of the UDP header and payload (at least 8 bytes).
  • Checksum (16 bits): Verifies integrity across the UDP header, payload, and IP pseudo-header (optional in IPv4, mandatory in IPv6).

TCP Connection

  • A TCP connection represents a logical, full-duplex communication session between two sockets (Source IP : Source Port and Destination IP : Destination Port).
  • Both peers track session parameters—such as sequence numbers, receive windows, and timers—until the session is closed or aborted.

Three-Way Handshake & Connection Establishment

TCP establishes a session using a three-step handshake to synchronize sequence numbers and verify bidirectional reachability:

  1. SYN: The client transmits a segment with the SYN flag set and an Initial Sequence Number (x).
  2. SYN-ACK: The server responds with SYN and ACK set, carrying its own Initial Sequence Number (y) and acknowledging x + 1.
  3. ACK: The client returns an ACK with acknowledgment number y + 1 (optionally carrying initial data). Once received by the server, the connection reaches the ESTABLISHED state.

Connection Release (Teardown)

Because TCP is full-duplex, each direction can close independently, typically via a four-way exchange (sometimes appearing as three packets when FIN+ACK or piggybacked ACKs occur):

  1. One endpoint (e.g., the client) finishes sending data and transmits a segment with the FIN flag set.
  2. The peer (e.g., the server) acknowledges the FIN with an ACK (closing the client-to-server direction while allowing server-to-client data to continue).
  3. Once the server has no remaining data to send, it transmits its own FIN segment.
  4. The client sends a final ACK, enters the TIME_WAIT state (allowing lingering packets from the previous session to clear), and then transitions to closed. (Alternatively, a connection can be reset immediately using an RST segment.)

Ports

  • Ports are 16-bit unsigned integers (0–65535) used by TCP and UDP to multiplex and demultiplex traffic so packets reach the proper service on a host.
  • Standard port ranges:
    • Well-Known Ports (0–1023): Reserved for core system and standard network services (e.g., 22 SSH, 25 SMTP, 53 DNS, 80 HTTP, 443 HTTPS).
    • Registered Ports (1024–49151): Assigned to specific applications or vendor-defined services.
    • Dynamic / Ephemeral Ports (49152–65535): Allocated temporarily by client operating systems when initiating outbound connections.
